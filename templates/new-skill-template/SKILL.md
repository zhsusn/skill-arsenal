# Skill 标题

## 适用场景
- 场景 1：描述何时应该激活此 skill
- 场景 2：另一个触发条件

## 核心职责
1. 职责一：明确 AI 在此 skill 下的主要任务
2. 职责二：补充任务范围

## 执行步骤（五阶段框架）

> 本 Skill 遵循 `docs/skill-execution-framework.md` 定义的五阶段三检查点执行规范。

### 阶段 1：输入分析（Input Analysis）
- [ ] **Schema 校验**：确认输入包含必要字段，格式正确
- [ ] **上下文加载**：读取前置依赖、项目规范（`AGENTS.md`）
- [ ] **来源识别**：区分用户直接输入 / 上游 skill 传递 / 外部 API 拉取
- [ ] **异常拦截**：输入为空或格式错误时，立即终止并返回结构化错误

> **Gate In**：输入不合法时，拒绝执行并说明原因。

### 阶段 2：条目整理（Task Decomposition）
- [ ] **需求拆解**：将任务拆分为可验证的原子任务清单（task_list）
- [ ] **优先级排序**：标记阻塞任务（Blocker）与可并行任务
- [ ] **范围冻结**：明确 In-Scope / Out-of-Scope，防止执行蔓延
- [ ] **资源评估**：预估 token、文件读写、外部调用次数

> **Gate Mid**：任务清单未整理完成前，不生成任何实质性输出。

### 阶段 3：原子执行（Atomic Execution）
- [ ] **单任务隔离**：逐项执行，失败不影响其他任务（或明确级联回退策略）
- [ ] **状态机管理**：跟踪任务状态 `pending → running → success / failed / skipped`
- [ ] **中间产物留存**：关键中间结果写入临时缓冲区
- [ ] **异常处理**：记录错误类型、输入快照、重试策略

### 阶段 4：覆盖验证（Coverage Validation）
- [ ] **条目回溯**：对照阶段 2 的 task_list，逐条验证输出是否覆盖
- [ ] **一致性校验**：检查输出与输入是否存在矛盾（数值、命名、范围）
- [ ] **边界测试**：验证空输入、超长输入、特殊字符等极端情况
- [ ] **幻觉检测**：对事实性内容标注来源；无法溯源的标记为 `[待验证]`

> **Gate Out**：未通过覆盖验证时，禁止交付最终输出，必须打回补执行。

### 阶段 5：总结归档（Retrospective）
- [ ] **执行摘要**：总结做了什么、用了什么资源、产出什么
- [ ] **问题沉淀**：记录阻塞、workaround、待优化点
- [ ] **模式提取**：判断是否需更新本 skill 的 prompt / 规则
- [ ] **归档存储**：按项目规则写入归档路径

## 输出格式
- **输出项 1**：格式要求和示例
- **输出项 2**：另一个输出要求

## 覆盖验证模板（阶段 4 速查）

```markdown
### 覆盖矩阵

| 来源条目 | 输出位置 | 状态 | 备注 |
|----------|----------|------|------|
| {输入条目 1} | {输出章节/文件} | ✅ 已覆盖 | — |
| {输入条目 2} | — | ❌ 遗漏 | 需补充到 {位置} |

### 一致性报告
- 数值一致性：{通过/不通过，详情}
- 命名一致性：{通过/不通过，详情}

### 幻觉检测
- [已验证] {事实 1} — 来源：{文件/URL}
- [待验证] {事实 2} — 需用户确认
```

## Gotchas
- **阶段 4 不可跳过**：未执行条目回溯和幻觉检测前，禁止输出最终产物
- **Gate Out 阻塞**：发现遗漏或矛盾时，必须列出清单等待用户确认，不得自动修复后静默通过
- **来源追溯**：每个事实性结论必须能指向来源数据中的依据；无法溯源的必须标记 `[待验证]`
- **范围冻结**：执行过程中若用户提出新需求，必须评估是否超出阶段 2 冻结的范围，超出则记录为"待后续迭代"

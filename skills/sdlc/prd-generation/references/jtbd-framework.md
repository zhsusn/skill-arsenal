# JTBD + 用户故事框架指南

> 参考来源：johnnychauvet/prd-skill 的 JTBD 框架与用户故事体系。用于确保需求表达从"为什么"出发，而非从"做什么"出发。

---

## 1. Jobs to Be Done（JTBD）格式

### 标准格式

```
When [situation], I want to [motivation], so I can [expected outcome].
```

### 填写规范

| 部分 | 说明 | 示例 |
|------|------|------|
| **When [situation]** | 用户处于什么具体场景？包含时间、地点、上下文触发条件 | "When 我需要在 24 小时内交付客户演示视频" |
| **I want to [motivation]** | 用户的真实动机是什么？避免功能描述，聚焦目标 | "I want to 一键生成带配音的分镜草稿" |
| **so I can [expected outcome]** | 用户最终要达成什么结果？量化或具体化 | "so I can 节省 80% 的脚本到成片时间" |

### 反例与正例

| 反例（错误） | 正例（正确） |
|-------------|-------------|
| "用户需要一个视频编辑器" | "When 制片人收到紧急商单时, I want to 在 48 小时内完成从剧本到成片的制作, so I can 不丢单并降低外包成本。" |
| "系统要支持导出 MP4" | "When 内容团队完成剪辑后, I want to 直接导出平台适配的竖版视频, so I can 跳过格式转换步骤。" |
| "做一个 AI 写作功能" | "When 编剧卡壳时, I want to 输入 3 个关键词就获得完整的场景对白, so I can 在 10 分钟内突破创作瓶颈。" |

### 优先级规则

按 **频率 × 重要性** 排序：
1. **高频且重要**：每日发生、直接影响核心指标 → 优先级 1
2. **中频但重要**：每周发生、影响关键体验 → 优先级 2
3. **低频但重要**：每月发生、影响决策/合规 → 优先级 3
4. **低频且次要**：偶尔发生、锦上添花 → 不纳入或放入 Phase 2+

## 2. 用户故事（User Stories）

### 标准格式

```
As a [role], I want to [action], so that [benefit].
```

### ID 编码规则

- 格式：`US-{模块编号}-{序号}`
- 示例：`US-001-001` 表示 PRD-001 模块的第 1 条用户故事
- 跨模块通用的用户故事使用 `US-COM-{序号}`

### 与用户故事与 JTBD 的映射

每个用户故事必须关联至少一个 JTBD：

| ID | Role | Action | Benefit | JTBD Ref | 优先级 |
|----|------|--------|---------|----------|--------|
| US-001-001 | 制片人 | 上传剧本文件 | 系统能自动解析角色和场景 | J1 | P0 |
| US-001-002 | 制片人 | 查看分镜时间轴 | 能调整镜头顺序和时长 | J2 | P0 |

### 验收标准（Acceptance Criteria）

每个 P0 级用户故事必须附带二元验收标准（通过/失败）：

```markdown
**US-001-001 — 上传剧本文件**
- [ ] 支持 .txt / .docx / .pdf 格式上传
- [ ] 文件大小 ≤ 10MB
- [ ] 解析完成后在 5 秒内显示角色列表
- [ ] 错误状态：格式不支持时显示明确错误提示
- [ ] 边缘情况：空文件上传时提示"文件内容为空"
```

### 编写原则

1. **可测试**：每个标准必须能明确判定通过或失败
2. **无歧义**：避免"快速"、"友好"、"正确"等主观词，改用具体数值
3. **覆盖错误状态**：至少包含正常路径 + 1 个错误路径 + 1 个边缘情况
4. **不预设实现**：写"用户可以导出视频"，而不是"点击导出按钮后调用 FFmpeg"

## 3. Component Inventory 映射

Component Inventory 是连接需求与实现的桥梁。每个组件必须追溯到一个或多个用户故事。

### 组件类型分类

| 类型 | 说明 | 示例 |
|------|------|------|
| **Form** | 数据输入组件 | 表单、搜索框、筛选器 |
| **Layout** | 页面结构组件 | 侧边栏、顶部导航、网格布局 |
| **Action** | 操作触发组件 | 按钮、下拉菜单、批量操作栏 |
| **Display** | 信息展示组件 | 卡片、表格、图表、时间轴 |
| **Navigation** | 路由/跳转组件 | 面包屑、Tab 切换、分页器 |
| **Modal** | 弹层/覆盖组件 | 对话框、抽屉、全屏预览 |

### 映射表模板

| 组件 | 类型 | 描述 | 关联用户故事 | 所属模块 | 优先级 |
|------|------|------|-------------|----------|--------|
| 剧本上传器 | Form | 支持拖拽上传，显示解析进度 | US-001-001 | 剧本工坊 | P0 |
| 分镜时间轴 | Display | 横向时间轴，支持拖拽调整 | US-001-002 | 分镜工作室 | P0 |

## 4. 快速检查清单

在输出需求前，逐条确认：

- [ ] 是否所有 P0 需求都有对应的 JTBD 支撑？
- [ ] 是否所有用户故事都关联了验收标准？
- [ ] 验收标准中是否消除了主观描述？
- [ ] Component Inventory 是否覆盖了所有 P0 用户故事涉及的界面？
- [ ] 模块名是否已统一为 kebab-case，并与 `feature-XX-{模块}/` 映射一致？

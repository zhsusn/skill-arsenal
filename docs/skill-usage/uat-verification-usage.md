# UAT Verification（用户验收测试）使用手册

> 版本：V2.4
> 适用 Skill：`skills/sdlc/uat-verification`
> 一句话定位：**集成测试通过了？别急着发布，先在预览环境走一遍真实业务流程，确认功能可用且流程走得通。**

---

## 1. 这是什么？

`uat-verification` 是你的"发布前最后一道质量门"。

集成测试（integration-test）验证了技术层面的接口和链路，但 UAT 验证的是**业务层面**——真实用户在真实场景下能不能顺利完成目标。比如：

- 用户能不能成功注册、登录、下单、支付？
- 表单提交后，页面跳转对不对？加载态、失败态有没有提示？
- 权限控制是否生效？未登录用户能不能访问敏感页面？
- 网络中断恢复后，数据有没有丢失？

**核心原则**：AI 负责生成清单和记录结果，**验证动作必须由人工在预览环境亲手执行**。

---

## 2. 适用场景

以下场景，强烈建议使用：

- 集成测试全部 P0 用例已通过，准备进入发布前验证。
- 需要基于用户故事生成可执行的检查清单。
- 预览环境 / staging 环境已部署，准备人工走查。
- 需要产出结构化的 `uat-report.md` 作为 Gate 3 签字依据。

**不适合的场景**：
- 集成测试 P0 用例未通过（请先修复）。
- 没有预览环境或 staging 环境（UAT 必须在独立环境执行）。
- 仅需要自动化测试（UAT 是人工验证，不可替代）。

## 3. 核心功能

### 3.1 四阶段流水线

| 阶段 | 做什么 | 谁负责 |
|------|--------|--------|
| **Phase 1** | 读取用户故事，生成/增强检查清单 | AI |
| **Phase 2** | 在预览环境按清单逐项操作验证 | **人工（不可替代）** |
| **Phase 3** | 根据人工反馈生成结构化 UAT 报告 | AI |
| **Phase 4** | 门控流转：通过 → Gate 3 签字；不通过 → 返工 | AI + 人工 |

### 3.2 清单增强

AI 不会从零生成清单，而是基于 `integration-test` 已产出的 `user-stories-checklist.md` 进行增强：

- 补充**具体操作步骤**（点击哪个按钮、填写什么字段）
- 补充**异常分支检查项**（重复名称、超长输入、网络中断恢复）
- 补充**权限验证项**（未登录访问、越权操作）
- 标注集成测试状态（已通过 / 待验证）

### 3.3 问题分级

UAT 发现的问题分为两级：

| 级别 | 定义 | 处理方式 |
|------|------|----------|
| **阻塞性问题** | 影响核心业务流程，导致用户无法完成目标 | 必须修复，生成 `rework-tasks.md` 返回开发 |
| **遗留问题** | 不影响核心流程的轻微问题（如文案、UI 微调） | 可记入下一迭代，有条件通过 |

**红线**：阻塞性问题未清零，不得进入 Gate 3 签字。

## 4. 使用方式（完整示例）

### 4.1 正常 UAT 流程

**场景**：集成测试通过，准备进入 UAT。

**对话：**

> **你**：集成测试通过了，准备 UAT。
>
> **AI**：收到。启动 `uat-verification` Skill。
>
> **AI**：**Phase 1: 生成验证清单**
> 已读取 `tests/integration/user-stories-checklist.md` 和 `specs/feature-*/user-stories.md`。
> 增强后的检查清单已保存。
>
> **AI**：**Phase 2: 人工验证（阻塞）**
> 请先在预览环境按 `user-stories-checklist.md` 逐项操作：
> 1. 正向流程：按用户故事完整走通
> 2. 异常分支：重复名称、超长输入、网络中断恢复
> 3. 权限验证：未登录访问、越权操作
>
> 操作完成后，请告诉我：通过 / 不通过 / 有条件通过，以及发现的问题清单。
>
> **你**：全部通过，无问题。
>
> **AI**：**Phase 3: 生成 UAT 报告**
> 已生成 `uat-report.md`：
> - 总体结论：通过
> - P0 用户故事验证率：12/12
> - 阻塞性问题数：0
> - 遗留问题数：0
>
> **AI**：**Phase 4: 门控流转**
> 请执行 `/skill:human gate=Gate3 action=sign-off` 完成 Gate 3 签字。
> 签字后进入 `requesting-code-review` 阶段。

### 4.2 UAT 发现阻塞性问题的场景

**对话：**

> **你**：支付后页面没有跳转到订单详情，还是停留在支付页。
>
> **AI**：收到。标记为 **阻塞性问题**：
> - 关联需求：FR-008（用户支付后查看订单）
> - 严重级别：P0
> - 复现步骤：...
>
> **AI**：UAT 结论为 **不通过**。已生成 `rework-tasks.md`，返回 `executing-plans` 修复。
> 修复完成后，请重新申请 Gate 3 sign-off。

### 4.3 有条件通过的场景

**对话：**

> **你**：核心流程都走通了，但发现登录页的提示文案有错别字。
>
> **AI**：收到。核心流程通过，文案问题标记为 **遗留问题**（P2，不影响核心流程）。
>
> **AI**：UAT 结论为 **有条件通过**。遗留问题记入下一迭代处理。

## 5. 输出产物说明

### 5.1 uat-report.md

结构化验收报告，包含：

- 总体结论（通过 / 有条件通过 / 不通过）
- P0 用户故事验证率
- 验证明细（需求编号 ↔ 结果 ↔ 问题描述）
- 问题清单（阻塞性 / 遗留）
- 与集成测试的交叉验证（发现测试覆盖盲区）
- 签字栏

### 5.2 rework-tasks.md（不通过时生成）

返工任务清单，格式与 `tasks.md` 兼容，包含：

- 关联 UAT 问题 ID
- 关联原始需求编号（FR-XXX）
- 修复任务描述
- 验收标准

### 5.3 uat-instructions.md（辅助文档）

人工执行指南，包含：

- 预览环境访问地址
- 测试账号与权限配置
- 需重点关注的 P0 链路
- 环境重置方法

## 6. 常见问题

### Q1：为什么 UAT 不能由 AI 自动执行？

因为 UAT 的核心价值是**真实用户的真实体验**。AI 无法模拟人类的直觉（如"这个按钮看起来太隐蔽了"）、上下文判断（如"这个流程在实际业务中不合理"）和跨设备体验（如"在手机上点击区域太小"）。

### Q2：集成测试都通过了，UAT 还会发现问题吗？

会。集成测试发现技术缺陷，UAT 发现业务逻辑和用户体验问题。两者互补，不可替代。常见的 UAT 专属发现：
- 流程跳转错误（技术正确但业务逻辑错误）
- 文案/提示不清晰
- 页面加载态/失败态缺失
- 跨浏览器兼容问题

### Q3：UAT 必须在什么环境执行？

必须在**独立环境**（staging / preview）执行，禁止在开发环境或生产环境直接验证。开发环境可能包含未完成的代码，生产环境直接验证风险太高。

### Q4：阻塞性问题和遗留问题的边界是什么？

| 阻塞性问题 | 遗留问题 |
|-----------|---------|
| 影响核心业务流程 | 不影响核心流程 |
| 用户无法完成目标 | 用户体验可优化 |
| 必须修复后才能发布 | 可延期到下一迭代 |
| 示例：支付失败、无法下单 | 示例：文案错别字、按钮颜色不统一 |

### Q5：UAT 不通过后返工，需要重新做集成测试吗？

视修复范围而定。如果修复的是前端页面跳转或文案，通常不需要重新跑全量集成测试。如果修复的是后端业务逻辑或数据库操作，建议重新执行相关 P0 用例。

### Q6：一个变更需要多轮 UAT 吗？

如果第一轮 UAT 不通过，修复后需要重新执行 UAT。但清单可以复用，只需重点验证修复项和受影响的相关流程。

## 7. 快速参考卡

### 7.1 触发口令

| 你想做什么 | 怎么说 |
|-----------|--------|
| 开始 UAT | "集成测试通过了，准备 UAT" / "开始用户验收测试" |
| 查看检查清单 | "打开 user-stories-checklist.md" |
| 反馈验证结果 | "全部通过" / "发现 X 个问题" / "有条件通过" |
| 查看 UAT 报告 | "打开 uat-report.md" |

### 7.2 UAT 检查清单速查

在预览环境操作前，确认：
- [ ] 预览环境地址可访问
- [ ] 测试账号和权限已配置
- [ ] 每个 P0 用户故事的正向流程已走通
- [ ] 异常分支已验证（重复、超长、空值、网络中断）
- [ ] 权限控制已验证（未登录、越权）
- [ ] 跨浏览器/跨设备已抽样检查（如适用）

### 7.3 问题分级速查

| 现象 | 级别 | 示例 |
|------|------|------|
| 核心流程无法完成 | 阻塞性 | 支付后未跳转、下单后库存未扣减 |
| 功能可用但体验差 | 遗留 | 文案错别字、加载速度慢、按钮太小 |

---

> **使用心法**：UAT 是发布前的最后一道人工闸门。很多团队跳过 UAT 直接发布，结果上线后才发现"功能可用但流程走不通"。记住：**集成测试保技术，UAT 保业务。两者都过了，才算真的准备好发布**。
